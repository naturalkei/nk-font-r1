# 테스트 자동화 계획 (`nkfont qa`)

> 2026-11-02 · 목표: 기능 개발과 테스트를 같이 진행해 오류가 사용자에게 가기 전에 잡는다.

## 1. 원칙

1. **명령 하나로 전부.** 개발자, CI, Claude 모두 `nkfont qa`를 실행합니다. 같은 명령이 같은 검사를 하므로 "내 컴퓨터에선 됐는데"가 없습니다.
2. **기능과 검사를 같은 PR에.** 새 기능(예: 이탤릭, 픽셀 출력)은 그 기능을 검증하는 검사 단계나 테스트를 함께 넣어야 병합합니다.
3. **버그는 회귀 테스트로 남긴다.** 고친 버그마다 합성 폰트로 재현하는 테스트를 `tests/`에 추가합니다.
4. **빠른 것부터.** 저장할 때마다 돌릴 수 있는 `quick`(약 15초), PR마다 도는 `ci`(약 3분), 릴리스 전에 도는 `release`로 나눕니다.
5. **결과는 기계와 사람이 모두 읽게.** `reports/qa.json`(기계), `reports/qa.md`(사람), GitHub Actions 요약 화면에 같은 표가 나옵니다.

## 2. 명령

```bash
nkfont qa                    # quick 프로필 (기본)
nkfont qa --profile ci       # PR 기준: 전체 weight + 실제 폰트 테스트 + Nerd Fonts 패치
nkfont qa --profile release  # ci + 수동 터미널 점검표
nkfont qa --update-golden    # 의도한 디자인 변경일 때 골든 이미지 갱신
nkfont diff old.ttf new.ttf  # 두 빌드의 구조 차이 (cmap, 폭, 외곽선, 메트릭, 이름, 기능)
make qa                      # = nkfont qa
```

실패하면 종료 코드 1을 돌려주므로 CI와 Git 훅에서 그대로 막을 수 있습니다.

## 3. 검사 단계

| 단계 | quick | ci | release | 잡아내는 오류 |
| --- | :---: | :---: | :---: | --- |
| lint (ruff check / format) | ✓ | ✓ | ✓ | 문법 오류, import 실수, 스타일 |
| 업스트림 폰트 검증 (SHA256) | ✓ | ✓ | ✓ | 원본이 바뀌거나 손상됨 |
| 단위 테스트 (합성 폰트) | ✓ | ✓ | ✓ | 병합·폭·메트릭·이름 로직 회귀 |
| 실제 폰트 통합 테스트 | | ✓ | ✓ | 실제 본고딕/JetBrains Mono에서만 생기는 문제 |
| 마스터 빌드 | Regular | 전체 | 전체 | 빌드 중단 |
| 폰트 검사: 폭 | ✓ | ✓ | ✓ | 터미널(wcwidth)과 advance 불일치 → 밀림 |
| 폰트 검사: 잉크 넘침 | ✓ | ✓ | ✓ | 글자가 옆 칸을 침범 → 겹침 |
| 폰트 검사: 메트릭·이름·기능 | ✓ | ✓ | ✓ | 줄 높이, Windows 잘림, RFN 위반, 합자 유실 |
| 재현 빌드 | ✓ | ✓ | ✓ | 같은 입력인데 다른 결과 (타임스탬프 등) |
| 골든 이미지 비교 | ✓ | ✓ | ✓ | 의도하지 않은 모양 변화 |
| Nerd Fonts 패치 + 패치본 검사 | | ✓ | ✓ | 패처가 폭·플래그를 망가뜨림 |
| 교정 시트 생성 | ✓ | ✓ | ✓ | 사람 눈으로 확인할 자료 |
| 수동 터미널 점검표 | | | ✓ | 자동화가 못 보는 실제 렌더링 |

판정: `pass` / `warn`(통과, 확인 권장) / `skip`(환경 없음, 예: Docker) / `fail`. `fail`이 하나라도 있으면 전체 실패입니다.

### 읽기용 가족 (NK Novel, NK Comics: `kind = "text"`)
* 터미널 격자가 없으므로 폭·잉크 넘침·고정폭 메트릭 검사 대신 `text-metrics`(고정폭 표시 금지, hhea = typo 줄 메트릭, USE_TYPO_METRICS, usWin이 bbox 포함)와 `hangul-coverage`(현대 한글 11,172자 전부)를 돌립니다. 이름(RFN)과 영문 기능 보존 검사는 같습니다.
* 골든 이미지는 본문 문장·따옴표·문장부호 샘플(`GOLDEN_TEXT_PROPORTIONAL`)로 렌더합니다.
* Nerd Fonts 패치 단계는 `skip`(설계상 아이콘 없음)입니다.
* 황금비 줄 높이(`line_height = "phi"`)는 `ascent − descent + lineGap = round(φ·UPM)`을 단위 테스트로 고정합니다.

### 잉크 넘침 판정
* 우리가 넣은 글리프(한글 등)가 칸을 5% 넘게 벗어나면 **실패**입니다.
* JetBrains Mono에서 물려받은 글리프(그리스 대문자 악센트, 일부 화살표)와 Nerd 아이콘(PUA, 비 Mono 변형은 의도적으로 넘침)은 **경고**로만 집계합니다.
* 이 검사로 실제 버그를 하나 잡았습니다. 본고딕의 "반각" 한글 자모(U+FFA0~FFDC)는 폭이 920이라 600 칸을 넘었고, 이제는 칸에 맞게 균등 축소합니다(`fit` 설정값).

### 골든 이미지
* `tests/golden/<폰트>.png`에 승인된 렌더링을 저장하고, 매번 같은 조건(HarfBuzz 없는 BASIC 레이아웃, 고정 크기, 흑백)으로 다시 그려 비교합니다.
* 픽셀 0.2% 넘게 바뀌면 실패하고 `reports/golden-diff/*.diff.png`(빨강=이전, 초록=현재, 파랑=차이)를 남깁니다.
* 디자인을 의도적으로 바꿨다면 `--update-golden`으로 갱신하고, PR에 바뀐 골든 이미지가 같이 올라가서 리뷰됩니다.

### 재현 빌드
* 같은 입력이면 바이트 단위로 같은 폰트가 나와야 합니다. `head.created/modified`를 고정(`SOURCE_DATE_EPOCH` 지원)해서 해결했고, `qa`가 한 번 더 빌드해 SHA256을 비교합니다.

## 4. 개발 흐름

1. 기능 브랜치에서 코드를 바꾸면 `nkfont qa`(15초)를 돌립니다.
2. 새 기능이면 검사 단계나 테스트를 같은 커밋에 추가합니다.
3. 모양이 바뀌는 변경이면 `nkfont diff`로 무엇이 바뀌었는지 확인하고, 의도한 것이면 골든을 갱신합니다.
4. PR을 열면 CI가 `nkfont qa --profile ci`를 돌리고 요약 표와 교정 시트를 올립니다.
5. 릴리스 전에는 `--profile release`의 점검표를 채웁니다.
